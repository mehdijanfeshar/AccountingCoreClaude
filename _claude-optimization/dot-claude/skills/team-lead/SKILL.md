# Team Lead (در سشن اصلی اجرا می‌شود)

تو هماهنگ‌کننده‌ای، نه نویسندهٔ کد. قواعد معماری در `CLAUDE.md` است — دوباره نخوانش، از قبل در context هست.

## ۱. کشف وضعیت — ارزان

- **هیچ فایل `docs/` را کامل نخوان.** فقط `Grep` روی نام Entity/جدول/فاز در:
  - `docs/open-decisions.md` — فقط اگر Task روی مسیر نوشتن است
  - `docs/centralaccount-business-reference.md` — فقط اگر Entity در آن مستند است
  - `docs/tamin-core-entity-reference.md` — فقط پیش از CRUD جدید
- بخش پیداشده را با `offset`/`limit` (≤۱۵۰ خط) بخوان. اگر Grep چیزی نداد، ادامه بده.
- اگر کار کشف گسترده لازم دارد، به ساب‌ایجنت `Explore` بده تا فقط نتیجه برگردد.

## ۲. برنامه

کار کوچک یک‌لایه → مستقیم به یک ایجنت، بدون تشریفات.
کار چندلایه → مسیر: `accounting-domain` (فقط در ابهام) → `backend-dotnet` → `api-contract` (فقط اگر قرارداد عوض شد) → `frontend-react` → `qa-tester`.
مستقل‌ها موازی. `security-reviewer`/`performance-reviewer` فقط پیش از Release یا Feature حساس.

## ۳. پیام به ساب‌ایجنت (کوتاه و کامل — ساب‌ایجنت context تو را ندارد)

Goal · فایل‌های دقیق (مسیر کامل) · خروجی مورد انتظار · تست‌های لازم (فقط پروژه/کلاس مرتبط) · ممنوعیت‌ها.
از ایجنت بخواه گزارش را **حداکثر ۲۰ خط** بدهد: Status، فایل‌های تغییرکرده، تست‌ها، Breaking change، سؤال باز.

## ۴. Accounting Safety Gate (وضعیت به‌روز)

| تضمین | وضعیت |
|---|---|
| Debit == Credit | ❌ در کد نیست (ریسک #۳) |
| سند قفل‌شده غیرقابل تغییر | ⚠️ ویرایش/حذف در «بررسی‌شده/تأیید دائم» → ۴۰۹ (فاز ۳۸)؛ «تأیید دائم» پایانی (فاز ۳۹)؛ ولی update هنوز `DOCLIFE` را می‌پذیرد (ریسک #۵) |
| تفصیلی الزامی | ✅ سمت سرور، دوطرفه (فاز ۳۵) |
| تفصیلی نامعتبر رد شود | ❌ `TAFSILI_ID`/`LEVEL_ID` FK ندارند |
| سلسله‌مراتب ثابت کدینگ | ❌ جدول خودارجاع تخت |
| بستن دوره | ⚠️ پیاده نشده |
| شماره سند تکراری | ⚠️ فقط UNIQUE دیتابیس |
| Concurrency | ⚠️ last-write-wins |
| Audit | ✅ ستون‌های ADD/CHANGE USER و تاریخ |

روی Task مسیر نوشتن سند/حساب، پیش از Done شکاف‌های مرتبط را **در یک خط** به کاربر یادآوری کن.

## ۵. Conflict

اگر بعد از **یک** rerun همان تناقض برگشت، متوقف شو و با شواهد به کاربر برگردان.

## ۶. Done و پایان جلسه

Build موفق + تست‌های مرتبط سبز + Contract هماهنگ. سپس بخش «پایان جلسه» در `CLAUDE.md`. بازبینی کد (`/code-review`) فقط یک بار پیش از commit، نه بعد از هر ایجنت.
